# Блок-схема: выбор максимально допустимого дебита (ГДИ)

Логика реализована в `src/modes/gdi_limits.rs` (`calculate_limits`).
Итоговый максимально допустимый дебит = **минимум** из ограничения по выносу песка
и ограничения по депрессии.

---

## Верхний уровень — `calculate_limits`

```
                ┌───────────────────────────────┐
                │  group пуст?                   │── да ──▶ LimitResult::default() (пусто)
                └───────────────┬───────────────┘
                                │ нет
                                ▼
        rows = group → сортировка по regime_no (№ режима)
        max_dep_limit = rows[0].max_dep   (или +∞, если нет)
        max_flo       = max(flo по всем режимам)
                                │
                ┌───────────────┴───────────────┐
                ▼                               ▼
   limit_sand_flo, comment           limit_dep_flo  (может менять comment)
   = calculate_sand_limit(...)       = calculate_dep_limit(...)
                └───────────────┬───────────────┘
                                ▼
              final_flo = min(limit_sand_flo, limit_dep_flo)
                                │
                                ▼
   Если (limit_dep_flo < limit_sand_flo) И comment=="ПЕСОК + ДЕПРЕССИЯ"
        → comment = "ДЕПРЕССИЯ + ПЕСОК"   (что строже — то и первым в тексте)
                                │
                                ▼
        dop_skv_flo = округл. вверх до 1000 (final_flo/1000+0.5 → пол → ×1000)
                                │
                ┌───────────────┴───────────────┐
         не конечно (NaN)               конечно
                │                               │
                ▼                               ▼
   только max_flo + comment      dop_skv_flo_percent_5 = округл. вниз до кратного 5000
   (без числовых лимитов)        dop_skv_flo_095       = округл. вниз до 5000 от (×0.95)
```

## Блок A — ограничение по **песку** (`calculate_sand_limit`)

Порог: `sand > 2.0` (`MAX_SAND`). Режимы рассматриваются **в порядке их проведения**
(сортировка по `regime_no`). Идея: безопасный дебит — это **максимальный чистый дебит,
оставшийся ниже связывающего песка** (`min_sandy`). Песочный режим считается **связывающим**
только если **после него скважина чисто на больший дебит уже не выходила**: если позже есть
чистый режим выше — ранний песок был транзиентным (разовый вынос) и НЕ ограничивает. Песок
ДО первого чистого режима — начальная промывка — тоже не считается.

```
sandy = режимы с sand > 2.0   (в порядке проведения)
   │
   ├─ sandy пуст ──────────────────▶ (max_flo,  "ГДИ")            ← песок нигде не превышен
   │
   ├─ sandy == все режимы ─────────▶ (0,        "ПЕСОК НА ВСЕХ РЕЖИМАХ!")
   │
   └─ часть режимов с песком:
        first_clean  = индекс первого чистого режима
        связывающие  = песочные режимы (начиная с first_clean), ПОСЛЕ которых нет
                       ни одного чистого режима с бо́льшим дебитом
        min_sandy    = минимальный flo среди связывающих песочных режимов
                       (не считаются: песок ДО first_clean и песок, перекрытый
                        последующим чистым более высоким дебитом)
        limit        = max(flo среди чистых режимов, где flo < min_sandy)
                       (если таких нет → 0)
        ⇒ (limit, "ПЕСОК")
```

Чистые режимы рассматриваются **независимо от их положения**: хвостовой чистый режим выше
раннего песка не только участвует сам, но и «снимает» этот песок со счёта (показывает, что
вынос был разовым). Связывает скважину самый низкий песочный режим, после которого скважина
чисто выше уже не выходила. Запаса в 5000 нет: берётся ближайший чистый дебит строго ниже
`min_sandy`.

**Пример 1** (скв. 1019 — ранний песок перекрыт последующим чистым выше):

```
flo     sand   →  состояние
 71400  0         чистый
 98300  3.42      ПЕСОК   ← перекрыт: позже есть чистый 101400 > 98300 → НЕ связывает
 69500  0         чистый
 80600  0         чистый
 94200  0         чистый
101400  0         чистый  ← скважина чисто ВЫШЕ раннего песка
107500  6.25      ПЕСОК   ← связывает (чисто выше после него не было) → min_sandy = 107500
100500  0         чистый
```

Связывающий песок — `107500`. Чистые ниже него — все шесть → **limit = 101400**
(ранний песок `98300` не ограничивает, т.к. скважина после него вышла чисто на `101400`;
прежняя логика ошибочно давала `94200`).

**Пример 1b** (хвостовой чистый берётся, если он ниже связывающего песка):

```
flo     sand   →  состояние
164700  0         чистый
 90900  0         чистый
115800  0         чистый
140400  14.36     ПЕСОК   ← перекрыт (позже чистый 180500/200000 выше) → НЕ связывает
166200  15.16     ПЕСОК   ← перекрыт → НЕ связывает
180100  2.8       ПЕСОК   ← перекрыт → НЕ связывает
202100  7.48      ПЕСОК   ← связывает → min_sandy = 202100
180500  1.4       чистый
165500  3.05      ПЕСОК   ← перекрыт (позже чистый 200000 выше) → НЕ связывает
200000  0         чистый
```

`min_sandy = 202100`. Максимальный чистый ниже него → **limit = 200000**.

**Пример 2** (песок в начале — начальная промывка):

```
flo     sand    →  состояние
110700  42.28      ПЕСОК   ┐ начальная промывка
112100  17.13      ПЕСОК   ┘ (до первого чистого режима — игнор)

```

`min_sandy = 84400` (110700/112100 — промывка, игнор). Чистые ниже него: `{56900, 71700}`
→ **limit = 71700**.

## Блок B — ограничение по **депрессии** (`calculate_dep_limit`)

Порог: `dep > max_dep_limit`. Рассматриваются только **чистые** режимы (`sand ≤ 2.0`);
песочные ограничены Блоком A.

```
dep_rows = чистые режимы, где есть и dep, и flo
   │
   ├─ dep_rows пуст ──────────────────────────▶ max_flo  (нет чистых данных по депрессии)*
   │
   bad_dep = ЧИСТЫЕ режимы с dep > max_dep_limit
   │
   ├─ bad_dep == 0 ──────────────────────────▶ max_flo  (на чистых режимах депрессия в норме)*
   │
   *  В обоих случаях число не меняется, НО если депрессия превышена на каком-либо
      режиме (в т.ч. ПЕСОЧНОМ — он и так ограничен Блоком A), в комментарий добавляется
      «ДЕПРЕССИЯ» (например «ПЕСОК» → «ПЕСОК + ДЕПРЕССИЯ»).
   └─ есть превышающие режимы  ("ДЕПРЕССИЯ" / "...НА ВСЕХ РЕЖИМАХ!"):
        │
        ├─ ВСЕ режимы выше лимита дали дебит МЕНЬШЕ самого слабого режима
        │  в пределах лимита (max(flo|dep>лимит) < min(flo|dep≤лимит)):
        │       индикаторная линия «перевёрнута» (рост депрессии → падение дебита) —
        │       это нестабильный замер, а не потолок. Депрессия НЕ ограничивает число
        │       (▶ max_flo, дальше его срежет песок), но «ДЕПРЕССИЯ» в комментарий пишется.
        │
        U (верхняя точка) = режим с МИНИМАЛЬНОЙ депрессией среди dep > лимита
                            (при равной депрессии — МЕНЬШИЙ дебит, консервативно)
        L (нижняя точка)  = режим с МАКСИМАЛЬНОЙ депрессией среди dep ≤ лимита
                            (при равной депрессии — больший дебит)
        │
        ├─ L существует И flo(L) ≤ flo(U)  (отрезок физичен, наклон ≥ 0)
        │       якорь = L
        │
        └─ иначе (L нет, или дебит падает с ростом депрессии)
                якорь = (0, 0)
        │
        ▼
   линейная интерполяция между якорем и U на x = max_dep_limit:
        если dep(якорь) == dep(U) → flo(якорь)
        иначе  flo = y_як + (x − x_як)·(y_U − y_як)/(x_U − x_як)
```

Частный случай «**депрессия на всех режимах**» (нет ни одной точки ниже лимита)
считается отдельно: прямая через `(0,0)` и режим с **минимальным дебитом**
(`flo_min, dep_min`), снятая на лимите: `limit = max_dep_limit · flo_min / dep_min`.
Это самая консервативная (нижняя) огибающая.

**Пример A** (well 105, отрицательный наклон → через `(0,0)`):

```
flo    sand  dep
28400  0     3.66   ← L? dep≤4, но flo(L)=28400 > flo(U)=24200 → наклон<0
40300  0     6.09
24200  0     4.18   ← U: минимальная dep среди > 4
...
```

Отрезок `L→U` убывающий (28400 → 24200) → якорь `(0,0)`:
`flo = 4.0 · 24200 / 4.18 ≈ 23158`.

**Пример B** (well 218, положительный наклон → между точками; песочный режим исключён):

```
flo    sand   dep
32600  82.85  1.25   ← песок → исключён из dep_rows
...
19900  0      1.36   ← L: максимальная dep ≤ 4 (при равной 1.36 — больший дебит)
21500  0      18.21  ← U: минимальная dep среди > 4
16200  0      1.36
```

Наклон положительный (19900 → 21500) → интерполяция `L–U`:
`flo = 19900 + (4.0 − 1.36)·(21500 − 19900)/(18.21 − 1.36) ≈ 20151`.

**Пример C** (well 422, депрессия на всех режимах → через `(0,0)` и min-дебит):

```
flo    sand  dep
47800  0     4.95
...
34600  0     5.38
31700  0     5.94   ← минимальный дебит
```

Все dep > 4 → прямая через `(0,0)` и `(31700, 5.94)`:
`flo = 4.0 · 31700 / 5.94 ≈ 21346`.

**Пример D** («перевёрнутая» индикаторная линия — единичный провал выше лимита):

```
flo     sand   dep
83600   0      4.47   ← U: единственный режим выше лимита, дебит < всех «хороших»
191600  12.28  2.64   ← песок → исключён из dep_rows (ограничен Блоком A)
188000  5.36   2.34   ← песок → исключён
166000  1.08   2.0    ← max дебит среди dep ≤ 4
...
98200   0      0.84   ← min дебит среди dep ≤ 4 (= 98200 > 83600)
```

Линия растёт до 166000 при dep 2.0, затем единственная точка при dep 4.47 «проваливается»
до 83600 — это ниже самого слабого замера в пределах лимита (98200). Депрессия не
ограничивает: число задаёт песок (связывающий песок 188000 → максимальный чистый ниже =
**166000**), а «ДЕПРЕССИЯ» остаётся в комментарии → «ПЕСОК + ДЕПРЕССИЯ». Без этого правила
экстраполяция через `(0,0)` к провалу дала бы абсурдные ≈ 74810.

## Ключевые нюансы

- **Режимы с `flo = 0`** (или без дебита) отбрасываются ещё до расчётов — они не
  участвуют ни в песке, ни в депрессии (иначе нулевой дебит «отравлял» бы
  интерполяцию депрессии).
- **Итог = `min(песок, депрессия)`** — берётся самое строгое из двух ограничений;
  порядок слов в комментарии отражает, что строже.
- **`max_dep_limit`** берётся из `max_dep` режима с наименьшим `regime_no`
  (первого после сортировки); если он `+∞` — ограничение по депрессии не срабатывает
  (`bad_dep == 0`).
- **Песочные режимы исключаются** из расчёта депрессии (ими занимается Блок A).
  Тонкость по дебиту при равной депрессии: для **верхней** точки `U` (среди режимов
  ВЫШЕ лимита) берётся **меньший** дебит — консервативная (нижняя) оценка; для
  **нижней** точки `L` (среди режимов в норме) — больший дебит.
- **Якорь в `(0,0)`** используется, когда нижней точки нет или отрезок к ней
  получается убывающим (нефизичным) — это даёт консервативную прямую через начало
  координат.
- **Округления на выходе:**
  - `dop_skv_flo` — вверх до 1000;
  - `dop_skv_flo_percent_5` — вниз до кратного 5000;
  - `dop_skv_flo_095` — вниз до 5000 от 95 % значения.
